# Joy-Con 姿勢・操作の検証

目的は、ひねり・左右・上下の操作を実測し、加速度・ジャイロのセンサー軸と画面への変換を確認することです。検証モードの持ち方・操作の選択は記録ラベルであり、補正方式を変更しません。

以下の姿勢・方向確認は Deadzone `120`・一方向の操作を使います。
動きの引っかかりを調べる場合は、後述の「引っかかり・一瞬の非表示の検証」に従い、
Deadzone `30`・左右往復で記録してください。両者は目的の異なる測定です。

## 設定と測定

1. 更新後のアプリを再起動し、R Joy-Con を接続する。
2. 平らな場所で静止させてキャリブレーションを完了する。
3. 補正方式「重力基準（自動）」、Speed `0.05`、Deadzone `120` にする。
4. 「姿勢・操作の検証モード」を有効にし、対象「R（右）」を選ぶ。ポインター非表示でも受信中と表示されることを確認する。
5. 持ち方・操作を選び、メモに握り方（ボタン面・先端の向き）、実際のポインターの動きを記載する。
6. 「2秒後から5秒記録」を押す。2秒の準備後、選択した操作だけを行う。往復せず、同じ方向の操作を記録する。
7. 記録ごとに「JSON保存」する。結果をコピーしてチャットへ貼り付けることもできる。次の記録開始で前回の記録は置き換わる。

最初に通常持ちで、静止、左、右、上、下、左ひねり、右ひねりを別々に測定します。その後、左・右へ45°または90°ひねって保持した姿勢で、左右・上下を測定します。

非表示の影響は「非表示でひねる→表示して左右へ振る」「非表示でひねる→表示して上下へ振る」を使います。ボタンを離してひねり、その姿勢のままボタンを押し、向きを変えます。各サンプルに実際の表示状態が残ります。

## 値の意味

- 生加速度・生ジャイロ: センサーから読んだ3軸値。軸の対応を推測する前にこの値を確認する。
- 加速度(G)・角速度(°/s): 現在のコードの換算係数による値。角速度はジャイロバイアスを除く。
- 推定重力・縦回転軸: 左右のセンサー向きを揃えた共通本体座標の単位ベクトル。生値の座標とは異なる。
- 閾値前の画面成分: 保持姿勢を補正した後、デッドゾーンを適用する前の横(Z)・縦(Y)成分。
- 閾値後の画面成分: デッドゾーン適用後の横・縦成分。
- 予定移動: 表示中と仮定した移動量。方向符号と速度を適用した論理ピクセル値。
- 実移動: 表示状態・キャリブレーション・画面端の制限を反映した、main プロセスの座標差分。描画側のスムージング後の測定値ではない。非表示中は0。

静止時はジャイロの残留値、ひねり時は反応する生ジャイロ軸と閾値前の画面成分、保持姿勢変更時は生加速度と推定重力の差を比較します。生値にひねりが出た時点でセンサー軸を特定し、補正後に横・縦へ混入する段階を調べます。

## 加速度換算修正後の再検証

加速度は `1/4096` で G に換算します。静止時の大きさが約1Gであることを確認してください。旧記録の `1/16384` 換算では約0.25Gとなり、重力方向の補正が無効になっていました。検証表示と実処理は同じ換算定数を使用します。

キャリブレーション成功時は古いポインター姿勢を破棄し、次の有効な加速度から重力方向を初期化します。一連の測定前に1回、台に置いて静止した状態で実施し、完了表示を確認してください。姿勢を変えるたびの再実施は不要です。

1. アプリを再起動し、Rを接続してキャリブレーションを完了する。
2. 補正方式「重力基準（自動）」、Speed `0.05`、Deadzone `120`、対象「R（右）」にする。
3. 通常姿勢で約2秒静止し、ポインターを表示して検証欄が「表示」であることを確認する。
4. 「2秒後から5秒記録」を押し、準備中は静止する。
5. 記録開始後、左右または上下へ20〜30°程度、1〜2秒かけて一方向へ向ける。その後は記録終了まで静止し、元へ戻すのは終了後にする。
6. 左・右・上・下を別々に保存し、画面上で動いた方向をメモする。ポインター位置に合わせて手の動きを変える必要はない。画面端に到達した場合はメモする。
7. 通常姿勢で追従を確認した後、非表示で左または右へ90°ひねり、約2秒保持してから表示する。その姿勢で左右・上下を同じ手順で記録する。
8. ひねりだけの測定は別記録にし、先端の向きをなるべく保ちながら長手方向の軸を中心に回す。

自動テストでは左右・上下の実測4記録を再生し、ずれた重力推定から準備時間中に復帰した後、移動方向と他軸への混入を検証します。これは実機での操作確認を代替するものではありません。

データ受信が途切れた場合は最終値であることを表示します。キャリブレーション中は姿勢更新が停止するため、補正値は参考値として表示・記録します。記録はブラウザー内のメモリーに保持し、持ち方・操作などの設定だけを localStorage に保存します。

## 引っかかり・一瞬の非表示の検証

### 測定手順

1. 最新ビルドでアプリを再起動する。配布版は `npm run package-win` が完了した後、
   `dist_packager/JoyCon Clicker-win32-x64/JoyCon Clicker.exe` を起動する。
2. R を接続し、静止させてキャリブレーション完了を待つ。一連の測定前に1回実施し、
   記録中には実施しない。補正方式「重力基準（自動）」、Speed `0.05`、Deadzone `30` にする。
3. 画面下部で検証モードを有効にし、対象「R（右）」・通常持ちを選ぶ。
   操作欄に該当する項目がなければ、メモに「静止」または「水平に左右往復」と明記する。
   設定値はメモとは別に JSON の `samples[].sample.settings` に記録されるため、実際の値も確認する。
4. X を押し続けてポインターを表示し、画面端から離れた位置に置く。
   「2秒後から5秒記録」を押し、準備2秒と記録5秒の間は静止したままにして、JSON を保存する。
5. 同じ設定でもう一度記録する。準備2秒は静止し、記録開始から終了までゆっくり左右往復する。
   手の振り幅を画面上の位置に合わせる必要はない。画面端に当たらない小さな範囲で振り、
   X は終了まで離さない。終了後に JSON を保存する。
6. 左右往復を数回記録し、症状の有無と、発生した場合は記録開始からおよそ何秒後かを共有する。
   保存前に次の記録を始めると前の結果は置き換わる。
7. 修正確認では設定を変えずに比較する。Deadzone の影響だけを比較する場合は `70` でも
   同じ動作を記録し、他の設定は変えない。手動接続と切断後の自動再接続も別途確認する。

### JSON バージョン2の測定イベント

`schemaVersion: 2` は従来のセンサーサンプルを維持し、`samples[].runtimeEvents` と、
それらをまとめたルートの `runtimeEvents` を追加します。同じイベントが両方に含まれるため、
解析時にはどちらか一方を使用してください。バージョン1にはこのイベント測定はありません。

| kind | 主な値 | 読み方 |
| --- | --- | --- |
| `device-scan` | `durationMs`、`discoveryDurationMs`、`batteryDurationMs`、`discoverySkipped` | 全体・列挙・電池情報要求の時間。列挙省略なら `discoverySkipped: true`、列挙時間0。 |
| `button` | `pressed` | RのXまたはLのDownの押下状態が変化した時刻。 |
| `visibility` | `visible` | アプリが受信した表示・非表示の通知。 |
| `render` | `maxFrameIntervalMs`、`maxUpdateIntervalMs`、`lastUpdateAgeMs` | 描画間隔・位置更新受信間隔の最大値と、最後の位置更新からの経過時間。 |

全イベントの `timestampMs` は Unix 時刻のミリ秒です。探索イベントは開始時刻、
その他は状態変化・通知受信・描画測定の時刻です。処理時間と間隔の単位も ms です。
非同期探索の `discoveryDurationMs` は完了までの経過時間であり、その間ずっとメイン処理が
止まっていたことを意味しません。`batteryDurationMs` は電池情報要求の同期処理時間で、応答待ちではありません。

描画測定は約250msごとに送信し、`visible`、`documentHidden`、`cssVisibility`、描画座標 `x`・`y` も含みます。
`lastUpdateAgeMs` は未受信の場合 null、`maxUpdateIntervalMs` は区間内に新しい間隔が確定していなければ0です。
したがって値0だけで更新停止がなかったとは判断せず、最後の受信からの経過時間も確認してください。
`cssVisibility` は要素に直接設定された値であり、OS の画面合成状態を示すものではありません。

イベントは検証モード有効時のみ最大256件まで保持し、次のセンサーサンプルと一緒に転送します。
記録先頭には直前のイベントが混ざることがあり、終了直前の未転送分は含まれないことがあります。
`timestampMs` とサンプルの記録期間を照合してください。探索周期を比較する場合、探索イベントが
含まれなければ再記録します。JSON 生データはリポジトリの追跡対象外です。

### 今回の修正と実機確認結果

修正前は約5秒ごとの同期デバイス列挙がメイン処理を止めていました。
修正後は未接続・接続処理中でない・自動接続が有効な対象がある場合だけ列挙し、
必要な列挙は `HID.devicesAsync()` で行います。接続済み機器の電池情報更新は継続します。
R のみ接続して L の自動接続が有効な場合は、L を探す非同期探索が続きます。
手動接続時の探索も非同期化し、重複探索と停止後の古い結果による接続を防いでいます。
滞留したセンサーデータの移動量計算と Deadzone の既定値は変更していません。

2026-10-04 の R・通常持ち・左右往復、Speed `0.05`・Deadzone `30`・重力基準での比較：

| 項目 | 修正前 | 修正後①・探索省略 | 修正後②・L未接続 |
| --- | --- | --- | --- |
| 記録ファイル末尾 | `1791110895673.json` | `1791111399973.json` | `1791111443118.json` |
| デバイス列挙時間 | 約299.8ms・同期 | 0ms | 約289.2ms・非同期 |
| 最大位置更新受信間隔 | 約310.8ms | 45.0ms | 約44.8ms |
| 最大描画間隔 | 約17.4ms | 約17.7ms | 約17.0ms |
| 操作者の体感 | 引っかかりあり | 引っかかりなし | 引っかかりなし |

修正前は列挙の時間帯にセンサー処理が311ms空き、再開後に21サンプルを約4msで処理しました。
修正後②では列挙中にも21サンプルを処理し、その区間の最大サンプル間隔は27msでした。
修正後の両記録に非表示への切り替えはなく、約0.3秒の停止が解消したことを確認できました。
修正前のメモは「Deadzone20」ですが、JSON内の実設定は30です。

これは各約5秒の測定と操作者の報告に基づく結果で、すべての環境での停止解消を保証するものではありません。
非同期列挙でも OS 側の Bluetooth 通信に影響する可能性は残るため、再発時は同じ方法で記録してください。
