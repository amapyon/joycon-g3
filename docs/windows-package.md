# Windows配布用アプリの更新

`npm run package-win` でビルド後、Windows x64用の配布物を作成します。更新前に、出力先から起動したアプリを終了してください。実行中のファイルがロックされている場合、更新は失敗することがあります。

依存設定を更新した後は、先に `npm install` を実行してください。ZIP展開で利用する `yauzl` は `extract-zip` に限定した overrides で `3.4.0` に固定しています。古い `2.10.0` と `fd-slicer` の組み合わせでは、Node v24.16.0 上でZIP展開が途中終了することを実測しました。

正常終了時は `作成完了（最新ビルドとの一致を確認）: ...` が表示されます。`Packaging app ...` だけでは完了ではありません。切り替え前に `dist/` の全ファイルと配布物の内容をSHA-256で比較し、欠落や相違があれば旧アプリを置き換えずエラーにします。非同期処理が未完了のままプロセスが終了した場合も、終了コードを失敗にしてメッセージを出します。

## 出力の切り替え

1. `dist_packager_next/JoyCon Clicker-win32-x64` に新アプリを生成し、本体の `JoyCon Clicker.exe` を確認する。
2. 既存の `dist_packager/JoyCon Clicker-win32-x64` を同じ親フォルダー内の `JoyCon Clicker-win32-x64.backup` へ退避する。
3. 新アプリのフォルダーを正式な出力先へ移動する。上書きコピーではないため、古いアプリにだけあったファイルは残らない。
4. 切り替え後の実行ファイル確認が成功したら、退避した旧アプリを削除する。

正式な出力先の親フォルダーは削除しません。そこに置かれた他のファイルは保持します。

## 失敗した場合

- 旧アプリの退避に失敗した場合は、旧アプリはその場所に残る。
- 新アプリへの切り替え・切り替え後の確認に失敗した場合は、旧アプリの復元を試みる。新アプリは一時出力先に残す。
- 復元にも失敗した場合は、エラーに表示されたバックアップと一時出力を保全し、内容を確認してから復旧する。
- バックアップが既に存在する場合は、上書きや自動削除をせず停止する。次の実行前に保管内容を確認する。

フォルダー切り替えはプロセス終了や電源断に対する完全なトランザクションではありません。切り替え途中で中断した場合も、バックアップを確認してください。ファイルの存在確認はアプリの起動成功を保証しないため、生成後は起動確認が必要です。

## Git・配布物から除外するデータ

リポジトリ直下の `joycon-validation-*.json`、`.electron-cache/`、`.packager-tmp/`、`.pnpm-store/` はGitと配布対象から除外します。データ自体は削除しません。`dist_packager_next/` も生成物としてGitから除外します。

`src/__tests__/fixtures/joycon-r-motion.json` は測定原本とは別の回帰テスト用データなので、引き続きGitで管理します。
